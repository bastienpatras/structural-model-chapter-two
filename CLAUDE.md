## The paper, in one paragraph

France enforced mandatory Energy Performance Certificate (EPC/DPE) disclosure in 2021.
Non-disclosing listings trade at a **premium** (6.9% apartments, 3.4% houses) over disclosed
low-efficiency listings — the opposite of classical unraveling. The paper resolves this using
private SeLoger listing data matched to the ADEME certified-audit registry, which gives direct
observation of each seller's information status (informed/uninformed × disclosed/hidden) —
normally unobservable to the researcher. It builds and structurally estimates a disclosure-game
model, derives a closed-form non-disclosure premium, and extends the model to endogenous
renovation to derive a minimum incentive-compatible retrofit subsidy. Target audience: top
real-estate and finance journals (the JMP framing follows the "strictest constraint wins the
front matter" rule in `paper-real-estate/PLAN.md` — write to JF/JFE/RFS convention, let the body
carry RE-specific depth).

## Core Principles

- **Plan first** — enter plan mode before non-trivial tasks; save plans to `quality_reports/plans/`
- **Contractor mode after approval** — once a plan is approved, execute it autonomously and
  return only for ambiguity or a real decision; more frequent check-ins during the first few
  sessions while the workflow is being calibrated. See
  [`collaboration-mode.md`](.claude/rules/collaboration-mode.md).
- **Verify after** — compile/render and confirm output at the end of every task
- **Single source of truth** — exhibits (figures/tables) are generated by `scripts/make_*.py` /
  `compute_subsidies.py` into `results/`, and `paper-real-estate/main.tex` points its
  `\graphicspath` and table inputs back at those generated artifacts (per `PLAN.md` decision 4:
  "fork with shared exhibits" — numbers must not drift between `paper/` and `paper-real-estate/`)
- **Quality gates** — see "Quality gates" below; **deferred** for this project, not disabled
- **`[LEARN]` tags** — when corrected, save `[LEARN:category] wrong → right` to `MEMORY.md`

Cross-session context lives in `MEMORY.md`; past plans, specs, and session logs are in
`quality_reports/`; paper-specific working notes (`PLAN.md`, `DIAGNOSIS.md`, `APPENDIX-GAPS.md`,
`FINDING-sigma1.md`, `V2-QUEUE.md`) live in `paper-real-estate/` itself and predate this port —
read them before starting substantive paper work, they carry real, hard-won context (e.g. the
σ₁ circularity finding, the ρ̂-boundary identification exposure).

**How we verify** — the references and rules that carry the verification discipline:

- [`verification-ladder.md`](.claude/references/verification-ladder.md) — the seven rungs, from
  *qualify the checker* to the external oracle.
- [`external-oracle-process.md`](.claude/references/external-oracle-process.md) — running an
  independent frontier-model referee and adjudicating what it returns.
- [`provenance-and-ground-truth.md`](.claude/references/provenance-and-ground-truth.md) — naming
  and pinning oracles, classifying divergence.
- [`review-fencing.md`](.claude/rules/review-fencing.md) — reviewer independence as a property of
  the environment (a neutral copy outside the checkout, prior verdicts withheld).
- [`release-engineering.md`](.claude/references/release-engineering.md) — shipping research
  software/replication packages.

**How we write** — [`writing-with-ai.md`](.claude/rules/writing-with-ai.md): `/humanize` is
**detect-only** — it reports AI-voice tells, it never auto-rewrites. A model cannot make its own
output stop reading as model-generated to a real detector; only genuine human rewriting does
that. See also [`proofreading-protocol.md`](.claude/rules/proofreading-protocol.md)'s
propose-then-approve-then-apply workflow, which the same discipline follows.

**Theory work** — [`theory-proving.md`](.claude/references/theory-proving.md): proof contracts,
counterexample-hunting your own lemmas, the rule that an AI-generated proof is a claim, not a
theorem. Directly relevant here — the model's propositions and the appendix proofs are exactly
this kind of claim.

**The laws** — [`research-agent-laws.md`](.claude/references/research-agent-laws.md): laws for
running agents on research infrastructure.

**How we remember** — the record lives in the repo, not the transcript:

- [`progress-reports.md`](.claude/rules/progress-reports.md) — GitHub issues as defect memory,
  `quality_reports/` as work memory, `MEMORY.md` as lesson memory.
- [`issue-ledger.md`](.claude/rules/issue-ledger.md) — the evidence standard an issue must meet.
- [`repo-hygiene.md`](.claude/rules/repo-hygiene.md) — **scratch must not become main.** Enforced
  by `check-repo-hygiene.py` on every commit (once `./scripts/install-hooks.sh` is run).

Nothing clears work until it has a row in
[`quality_reports/qualification/LEDGER.md`](quality_reports/qualification/LEDGER.md) — run

`rental-disclosure-claude`'s own content; that qualification does not transfer automatically —

## Quality gates — **deferred for this project**

The rental-disclosure-claude template enforces a numeric 80/90/95 quality score
(`quality_score.py`) on `.qmd`/`.tex`/`.R` files via `/commit` and the pre-commit hook. That
rubric was built for **Quarto/Beamer/R lecture materials** and has not been adapted to paper
prose — porting it unchanged would score this manuscript against criteria that don't apply
(slide overflow, Quarto div nesting, R-lecture code conventions).

**What's active instead:** the pre-commit hook (`.githooks/pre-commit`) runs the full
`backtest.sh` gate suite (repo hygiene, link integrity, skill/spec conformance, staleness,
derived-count drift) on every commit. It does **not** run a prose quality score. Substantive
paper review runs through `/review-paper`, `/seven-pass-review`, `/humanize`, `/proofread`, and
the two project-specific agents below instead — each returns a pass/fail or a structured report,
not a number.

If you want a prose-specific quality rubric later (e.g. one built from `DIAGNOSIS.md`'s
structural checklist + the AI-voice-tell categories), that's a deliberate follow-up, not
something inferred silently from this port.
