## 0. Lead finding: are the σ₁ circularity and ρ̂-boundary issues still live?

**Short answer: ρ̂-boundary — handled well, in both code and text. σ₁ circularity — honestly
disclosed in the prose, but *not* fixed in the reproducible pipeline, and the fix that does exist
lives outside version-controlled, reproducible code.** This is more nuanced than either
`FINDING-sigma1.md` (written 2026-08-12, mid-investigation) or the project's more recent memory
note ("σ̂₁_m=0 across 140 markets, primary validation") suggests. Neither is quite right about the
current state.

### 0.1 σ₁ circularity — three separate claims, three separate answers

1. **Is the tautology still in the code?** Yes, `src/data_prep.py:142` still defaults
   `merge_datasets(..., hider_theta="impose_zero")`, and — more importantly — **both production
   configs pin it explicitly**: `config_apartment.json` and `config_house.json` both set
   `"hider_theta": "impose_zero"`. `run.py:81` has its own default of `"registry"`
   (`cfg.get("hider_theta", "registry")`), but the committed config files override it back to the
   circular assignment. The registry-based fix that `FINDING-sigma1.md` recommended exists in the
   code (`data_prep.py:210-229`, `run.py`'s `"registry"` branch) but **is not what generates the
   published results.** `results/apartment/results.txt` and `results/house/results.txt`
   (timestamped 2026-08-12, matching the config files) show `σ̂₁_m ≡ 0.000` for every market —
   the signature of `impose_zero`, not of a measured quantity.

2. **Does the paper still claim σ̂₁=0 as validation?** No — and this is the genuine, good-faith
   fix since `FINDING-sigma1.md` was written. `sections/04-structural-draft.tex:60-71` (§4.1,
   "Motivation") now states plainly: *"we are explicit about what the model does not settle …
   it maintains Corollary cor:hq_disclose, σ₁\*=0, rather than testing it. Informed
   non-disclosers are assigned low quality by revealed preference, which is an assumption and not
   a result."* `sections/A-robustness.tex` reports the registry-based alternative as an appendix
   robustness table. This is the correct epistemic move, and it is a real improvement over the
   circular framing `FINDING-sigma1.md` caught.

3. **Does the robustness check itself hold up, and is it reproducible?** Two problems remain,
   neither flagged by the project's own notes:
   - **The robustness check is scientifically weaker than the appendix prose suggests.** At the
     baseline A–D threshold, `σ̂₁ = 5.1%` vs. `σ̂₀ = 5.5%` for apartments (a 7% gap) and `2.1%` vs.
     `2.2%` for houses (a 5% gap) — both differences are well within what a formal test would call
     noise at typical market sample sizes, and `A-robustness.tex:75-84` itself reports that the
     ordering **reverses** under the C–D threshold (6.5% vs. 4.8%, and 2.5% vs. 1.9% — the
     "wrong" direction, and by a larger margin than the A–D "right" direction). The text's own
     characterization — *"we read as support for the baseline cut rather than as independent
     confirmation of the corollary"* — is honest about this, but a reader skimming just the
     headline sentence ("the model's predicted ordering holds") could walk away with more
     confidence than the numbers support. **Recommendation: report a formal test (paired
     difference across markets, or the market-level t-stat) rather than only the pooled ratio, and
     state the C–D reversal in the same sentence as the A–D "support," not two sentences later.**
   - **The robustness table is not reproducible from the committed pipeline.** The six comparison
     runs behind `tab:robustness` live in `results/_robust/{apartment,house}_{legacy_impose,legacy_registry,core_registry}/`
     — six directories with no README, generated by manually toggling `hider_theta` and
     `epc_threshold` outside of `run.py`'s normal config-driven flow (there is no
     `scripts/make_robustness_table.py` or equivalent). `results/_sigma1test_impose_zero/` and
     `results/_sigma1test_registry/` are a second, separate pair of one-off runs. None of this is
     wired into `run.py`/`main.py` as a reproducible robustness step. A third party (or you, in six
     months) cannot regenerate Table `tab:robustness` by running the documented pipeline — only by
     reverse-engineering which config edits produced which scratch directory. This is exactly the
     failure mode `.claude/rules/repo-hygiene.md` names ("scratch must not become main") applied to
     a load-bearing appendix table rather than a stray script.
   - **The validation battery's own test is still tautological under the maintained config.**
     `src/validation.py:44-108`, `test_sigma1_zero`, is wired into `main.py`'s
     `run_all_validation()` (`main.py:78,411`) as one of the model's official "testable
     implications." Run against `market_stats` produced under the default `impose_zero`
     assignment, `sigma_1_hat` is identically 0 for every market by construction, so this test
     **cannot reject** regardless of what the data show — it will always log "0/N markets reject
     H₀." Nothing in `main.py`'s CONFIG dict overrides `hider_theta`, so this vacuous result is
     what the "official" validation entry point produces by default. (Separately, `main.py` appears
     to be a largely superseded single-property-type entry point — see §3 below — so this may be a
     dead code path rather than something actually run before submission; but it is still shipped,
     documented as part of the validation suite, and would mislead anyone who runs it expecting a
     real test.)

**Net assessment:** the paper text is honest about the σ₁ assumption — a genuine and welcome
correction from the circular framing `FINDING-sigma1.md` caught in August. But the *engineering*
of the fix stopped short: the corrected specification is not the default, not what produced the
published tables, and not reproducible from committed, run-once code. **This is the single most
important actionable item in this review** — not because the paper misrepresents what it found
(it doesn't, on a careful read of §4.1 and Appendix A), but because the current state invites a
future regression: anyone who reruns `run.py` with the committed configs reproduces the circular
statistic, and anyone who trusts `APPENDIX-GAPS.md`'s "← IMPLEMENTED" tags (see §0.3) would
reasonably but incorrectly believe this is settled.

### 0.2 ρ̂-boundary exposure — well handled

This one is in good shape. `sections/04-structural-draft.tex:409` and `:524-526` give the exact
counts (40/42 apartment partial-pooling markets, 54/76 house markets at the ρ̂=1 boundary; 22
house markets with interior identification) and state the consequence plainly: *"ĉ₀,m is
interpreted as an upper bound."* §4.1's Motivation paragraph previews this before the reader
reaches the estimates ("we do not purport to estimate the one true model … we maintain ρ̂_m = 1 …
and treat ĉ₀_m as an upper bound accordingly," `04-structural-draft.tex:68-71`). The code's
`estimate_msm(fix_rho=True)` path (`src/estimation.py:339-383`) implements exactly the closed-form
inversion the text describes, with the clip visible at line 353
(`np.clip(rho_m * beta1_m * e_star, 0.0, None)` — note this only clips the *lower* bound to 0; the
upper clip to 1 must happen upstream, in the DiD stage `estimate_rho_c0`, which this review did
not independently re-derive — worth a spot check if not already done). This is a real, disclosed
identification weakness handled the way `.claude/rules` calls for: named, quantified, and built
into the interpretation of the headline number rather than buried.

## 1. PROJECT SUMMARY

The paper studies France's 2021 mandatory Energy Performance Certificate (EPC/DPE) disclosure
reform and documents a puzzle: listings that do not disclose an EPC score trade at a **premium**
over disclosed low-efficiency listings (6.9% apartments / 3.4% houses, per the abstract and
`tab:did_results`), the opposite of what classical unraveling (Grossman/Milgrom) predicts. The
resolution is that non-disclosure pools two populations buyers cannot tell apart: informed sellers
strategically concealing a low score, and genuinely uninformed sellers with no certified audit.
Because the second group is large, silence remains ambiguous rather than damning.

The empirical strategy has two layers. First, a reduced-form DiD/event-study layer exploits the
July 2021 reform (when the EPC became legally opposable) as a shock to the salience/enforceability
of disclosure, comparing price paths across EPC-disclosure categories before and after, both in a
pooled hedonic index (§2/`03-setting-draft.tex`) and market-by-market (§4.4). Second, a structural
layer — a static, one-shot Dye (1985)/Jung–Kwon (1988) disclosure game with an added dimension of
heterogeneous buyer EPC-sensitivity (ρ) — is estimated market-by-market via a two-step procedure:
ρ̂_m is read off the DiD non-disclosure-premium-to-quality-premium ratio (clipped to [0,1]), then
ĉ₀_m (the structural concealment cost) is recovered by inverting the equilibrium indifference
condition given ρ̂_m and the measured hiding rate σ̂₀_m. The paper's distinguishing empirical asset
is a match between private SeLoger listing data and the ADEME certified-audit registry, which
gives direct observation of each seller's information status K — normally a latent variable in
disclosure models — letting the four-cell (d,K) classification (truthful disclosure / strategic
hiding / uninformed / falsification) be measured rather than inferred.

The model is then extended to an endogenous renovation margin, deriving a closed-form renovation
threshold and a minimum incentive-compatible subsidy S*_m, with a regime-dependent comparative-
statics result (disclosure enforcement and renovation subsidies are policy complements outside the
"Complete Adverse Selection" corner, substitutes inside it) as the paper's structural payoff — the
object a reduced-form design could not deliver on its own. The codebase (`src/`) implements data
prep/classification, hedonic regression, DiD event study, the equilibrium solver and MSM/two-step
estimator, and subsidy-grid computation, orchestrated by `run.py` (config-driven, per property
type) and a partially redundant `main.py` (single-type, with synthetic-data testing support).
Target audience is top real-estate/finance journals, with the job-market framing explicit in
`CLAUDE.md` and `PLAN.md`.

## 2. WHAT LOOKS SOLID

- **The K-observability design is the paper's real methodological contribution, and it is
  correctly exploited.** Most disclosure papers must infer whether a non-discloser was informed;
  here `K` is measured via the ADEME match (`src/data_prep.py:138-237`), and the paper is explicit
  that this is what lets it separate constrained silence from strategic silence
  (`04-structural-draft.tex:9-30`). This is a genuine identification advantage over the Dye/Jung–
  Kwon lineage it extends, and the paper states the comparison correctly.

- **The pre-trend/timing argument for the reform's causal interpretation is well constructed and
  specific, not generic.** `04-structural-draft.tex:41-48` gives a falsifiable timing test (a
  supply-side confound would have to move *both* β̂₁,m,t and Δ̂_m,t abruptly, on the same date, in
  the same markets, while leaving the non-disclosure share unchanged) and then checks it against
  the actual flat non-disclosure share in the apartment segment. This is a stronger identification
  argument than "DiD + parallel pre-trends" alone, and it is specific to this design rather than
  boilerplate.

- **The closed-form invariance result (premium = c₀, independent of π and ρ, in the interior
  partial-pooling regime) is a real theoretical payoff, correctly load-bearing in the empirics.**
  `04-structural-draft.tex:279-298` derives it and explains the economic mechanism (the indifference
  condition pins the premium regardless of composition); the estimation code's two-step inversion
  (`estimation.py:339-383`) is the direct computational embodiment of exactly this closed form —
  paper and code agree on the object being estimated and on why the inversion is valid only in this
  regime.

- **The disclosure of both major identification weaknesses (ρ̂ boundary, σ₁ assumption) inside the
  model section itself, before the estimates are shown, is good practice and increasingly rare.**
  `04-structural-draft.tex:60-72` states both limitations in one paragraph, in plain language
  ("we do not purport to estimate the one true model … we propose one way of reading these data").
  This is the right register for a referee, and it is backed by real quantification elsewhere in
  the same section, not just a hedge.

- **The regime-dependent policy-complementarity result (§ Policy Extension,
  `main.tex:190-232,781-786`) is a genuinely non-obvious, model-delivered finding**, not a
  restatement of the reduced-form facts: substitutability between enforcement and subsidies
  holds only in the corner (Complete Adverse Selection) regime, and the mechanism (the equilibrium
  indifference condition absorbing changes in c₀ through Π(d=0;e*) in the interior regime) is
  correctly derived and correctly cross-referenced against the estimated regime classification.

## 3. MAIN ISSUES

### Theory / Model Issues

**T1. The `α_k = β_k` benchmark (buyers trust unverified quality claims as much as verified ones)
is maintained throughout the estimated model, but the paper's own text notes the natural
alternative (`α_k < β_k`, the "distrust discount") would change the sign/magnitude of exactly the
result under stress (σ₁* = 0).** `FINDING-sigma1.md §4b` (and the paper's own
`04-structural-draft.tex:203`) note that c₁ — the mechanism that could rationalize high-quality
informed sellers withholding — is inert under the benchmark and only becomes binding under
α_k < β_k. Since the registry-based check (§0.1 above) shows the σ₁*=0 prediction is, at best,
weakly and reversibly supported, this is not a free-standing modeling choice — it is the
assumption load-bearing for the one prediction that is closest to failing. **Severity: Important.**
Concretely improves with: either (a) estimate α_k < β_k as an extension and show the U-shaped
hiding-rate-by-quality pattern documented in `FINDING-sigma1.md §3c` is better explained by it, or
(b) explicitly scope the paper's claim to "conditional on α_k=β_k" wherever σ₁*=0 is invoked.

**T2. The binary θ discretization is a strong modeling choice imposed at a single threshold that
also does double duty as the DiD "high group" cutoff — the paper acknowledges this but the two
thresholds are not independently justified.** `A-robustness.tex:56-61` notes "the quality
threshold also governs the price-index contrast" — i.e., the same cut used to binarize θ for the
structural model is also the cut that defines which price index counts as "high group" in the DiD.
A threshold chosen partly on institutional grounds (rental-ban discontinuity) and partly because it
is convenient for both purposes at once is a coupling a referee will ask about. **Severity:
Minor-to-Important**, mitigated by the sensitivity table already provided, but not eliminated by
it (see 0.1's point about the ordering reversal).

**T3. `γ₀=0, γ₁=1` (listing price ≈ transaction price) remains an assertion supported only by
external citations, never validated against the paper's own transaction data.**
`04-structural-draft.tex:99` and its footnote cite Merlo & Ortalo-Magné-type France-specific
negotiation-margin evidence, but `APPENDIX-GAPS.md` item 7 (not marked implemented, correctly) asks
for exactly the regression the paper has the data to run and hasn't. This assumption directly
rescales `c₀`'s units (per the assumptions-table language `APPENDIX-GAPS.md` quotes). **Severity:
Important** — a cheap, high-value check that is still open.

### Identification / Econometrics Issues

**E1 (elaborated in §0.1). σ₁ circularity is disclosed in text but not fixed in the production
pipeline; the registry-corrected specification is not reproducible from committed code.**
**Severity: Critical** (reproducibility/integrity dimension) even though the *paper's claims* are
currently honest about it — the risk is prospective (next regeneration silently reverts to the
circular number) and the appendix table's own provenance is not auditable.

**E2. No inferential uncertainty is reported anywhere for the structural parameters (ρ̂_m, ĉ₀_m,
σ̂₀_m).** `config_apartment.json`/`config_house.json` both set `"n_boot": 0`; the production
`results/{apartment,house}/` directories contain no `bootstrap_draws.csv`; and
`main.tex`/`04-structural-draft.tex`'s Table `tab:did_results` (`04-structural-draft.tex:455-484`)
reports only cross-market **Std** (heterogeneity across the 45/97 markets), which is honestly
labeled as such (not mislabeled "SE") but is a different object from a sampling standard error and
will be read by some readers as one. The bootstrap machinery exists and is well-designed
(`src/estimation.py:562-693`, correctly re-draws σ̂₀,m per bootstrap sample rather than holding
`market_stats` fixed — the code comment at `estimation.py:629-636` shows real care was taken to
avoid a zero-SE bug here) but is simply never invoked with `n_boot>0` for the numbers that ship.
The one place bootstrap SEs are auto-generated, `results/tables/table_estimates.tex`, shows literal
`(0.0000)` — a placeholder that would read as implausibly precise if it were ever pulled into a
manuscript. **Severity: Critical** for a paper heading to a top journal — referees will ask "what
is the standard error on ĉ₀," and there is currently no answer, even though the code to produce one
exists and is not obviously expensive (45 + 97 markets × 500 bootstrap draws).

**E3. The `weighting_scheme: "optimal_gmm"` config field is inert for the estimator that actually
produces the published numbers.** `estimate_msm(fix_rho=True)` (`estimation.py:339-383`, the
two-step "primary estimator" per `DIAGNOSIS.md` and confirmed here) performs a closed-form
inversion and never touches `weighting_scheme`, `build_weighting_matrix`, or any GMM machinery —
those are used only in the `fix_rho=False` joint mode that the project's own notes call
under-identified. The config file nonetheless declares `"weighting_scheme": "optimal_gmm"`, which
would mislead a reader of the config (or of `main.py`'s config-summary log) into thinking GMM
efficiency weighting is operative in the headline estimates. **Severity: Minor** (the paper's prose
correctly describes the two-step estimator; this is a config/code presentation issue, not a paper
claim), but cheap to fix — drop or comment the field, or assert in code that it's ignored under
`fix_rho=True`.

**E4. Table `tab:did_results`'s own footnote contradicts its own column values.**
`04-structural-draft.tex:467-468` (Panel A) reports **N=49** (apartments) / **N=104** (houses) in
the table body, but the footnote at `:482` states *"N=43 apartment markets after excluding 25 with
β̂₁,m≤0; N=107 house markets after excluding 6."* 49≠43 and 104≠107. The in-table N=49 matches
`results/apartment/results.txt`'s own reported "Markets with β̂₁_m > 0 (usable): 49," so the
footnote appears to be the stale number (likely from an earlier sample-construction pass, possibly
predating the 2021H2 exclusion documented at `:446`'s footnote). **Severity: Important** — this is
exactly the kind of internal inconsistency a referee catches in the first read of the results
table, and it is a five-minute fix once the correct number is confirmed against current
`results/*/results.txt`.

**E5. Two distinct "non-disclosure premium" point estimates coexist in the paper without being
reconciled or cross-referenced.** The headline (abstract, and `tab:did_results` Panel A,
`Δ̂_m`) is **6.9% (apartments) / 3.4% (houses)** — the cross-market mean of market-level DiD
estimates. Section 2's own Figure `fig:fact1_premium` discussion (`03-setting-draft.tex:129`)
reports a *different* number for what reads as the same underlying quantity — the pooled,
composition-adjusted event-study DiD stabilizing at **+0.044 log points (apartments) / +0.037
(houses)** — i.e., 4.4%/3.7%. These are plausibly different estimands (market-level mean of
market-specific DiDs vs. a single DiD run on a pooled/aggregate index), which is a legitimate
methodological choice, but the paper never states that they are different objects or why one is
preferred as "the" headline number over the other. `DIAGNOSIS.md` flagged this exact tension
in August (attributed then to a different paper's estimate; that specific misattribution appears
resolved — the abstract's 6.9%/3.4% now matches this paper's own Table 4) but the two-numbers
problem itself persists in a new form. **Severity: Important.** Fix: one sentence in §2 or §4.1
naming both numbers and stating explicitly which is the aggregation the paper leads with and why.

**E6. The identifying assumption behind ρ̂_m's numerator/denominator (composition bias in Δ̂_m,
thin-cell attenuation in β̂₁,m) is named but not bounded.** `04-structural-draft.tex:409-411`
correctly diagnoses *why* the unconstrained ρ̂ ratio exceeds 1 in all 40 apartment markets (mean
≈7.7×) — composition bias inflating the numerator, thin cells deflating the denominator — but does
not attempt to sign or bound the net effect, so the reader cannot tell whether ρ̂_m=1 in the clipped
markets is "probably close to true ρ" or "wildly overstated by a mechanical artifact." Given that
the majority of markets are clipped, this is the single largest source of uncertainty in the
paper's headline structural number, and it currently gets a qualitative diagnosis rather than a
quantitative bound. **Severity: Important** — a natural companion to E2 (bootstrap ρ̂_m's numerator
and denominator separately to see how much of the >1 ratio survives sampling noise vs. reflects the
named composition/attenuation biases).

### Code / Reproducibility Issues

**C1. Two partially-divergent pipeline entry points (`main.py`, `run.py`) with different default
configurations, and it is not obvious from the repository which one is authoritative.**
`main.py`'s in-file `CONFIG` dict has no `hider_theta` key at all (falls through to
`data_prep.py`'s function default, `"impose_zero"`) and defaults `n_boot=500`; `run.py` is
config-JSON-driven per property type and currently ships `n_boot=0`, `hider_theta="impose_zero"`
via the committed configs. Timestamp evidence (`results/apartment/*.csv` at 2026-08-12 22:36,
matching `config_apartment.json`'s mtime) indicates `run.py` + the committed configs produced the
published results, not `main.py`. `CLAUDE.md`'s own folder-structure table lists "`main.py, run.py`
— Structural model entry points" without distinguishing them. **Severity: Important** — a
replicator (or a future you) has a real chance of running the wrong entry point and getting
different numbers with no error message explaining why. Recommend: either delete/archive `main.py`
per `.claude/rules/repo-hygiene.md` ("anything you would not defend in a code review does not get
committed as a main file"; an unused, drifted duplicate pipeline is exactly this), or add a
top-of-file note in each pointing at the other and stating which is canonical.

**C2. `paper-real-estate/main.tex` and its sections do not `\input{}` any table from
`results/tables/`, contradicting `CLAUDE.md`'s own stated invariant.** `CLAUDE.md` §"Core
Principles" states: *"exhibits (figures/tables) are generated by `scripts/make_*.py` /
`compute_subsidies.py` into `results/`, and `main.tex` points its `\graphicspath` and table inputs
back at those generated artifacts … numbers must not drift."* In the current tree, **figures** do
follow this pattern (`\includegraphics{fig/visuals/...}`, `fig/stylized_facts/...}` etc., all
sourced from a generated `fig/` tree) — but **every numeric table in `main.tex` and its sections is
typed directly as literal LaTeX**, not `\input` from `results/tables/*.tex`. Concretely,
`results/tables/table_estimates.tex` exists, is machine-generated (confirmed: it contains the
placeholder `(0.0000)` bootstrap SEs from E2), and is referenced **nowhere** in the manuscript.
Tables `tab:did_results`, `tab:robustness`, `tab:listing_types`, etc. are all hand-transcribed. This
is precisely the drift risk `CLAUDE.md` was written to prevent, and E4 (the N=49-vs-43 footnote
inconsistency) is a concrete instance of exactly that drift having already happened. **Severity:
Critical** for reproducibility/integrity, even though (on current spot-checks) the transcribed
numbers substantively match `results/*/results.txt` — the mechanism guaranteeing that match is a
person, not a build step.

**C3. `src/validation.py`'s stated "testable implications" battery is not actually run against the
paper's estimation sample in a way that is visible in the repo.** `test_sigma1_zero` (§0.1),
`test_premium_sign`, `test_premium_decreasing_in_pi`, and `overidentification_test`
(`validation.py:44-247`) are well-specified functions, but there is no committed script or notebook
cell that runs them against `results/apartment` / `results/house` and writes output a reader (or a
future reviewer) can inspect. `run_all_validation` is called only from `main.py`, which — per C1 —
is likely not the pipeline that produced the published numbers. **Severity: Minor-to-Important** —
the validation code exists and looks reasonable; the gap is that its output isn't part of the
reproducible record.

**C4. Numerical-safety spot check.** `estimation.py:353` clips ĉ₀_m's lower bound
(`np.clip(rho_m * beta1_m * e_star, 0.0, None)`) but this reviewer did not independently trace where
ρ̂_m's *upper* clip to 1 is applied (referenced in prose at `04-structural-draft.tex:409` and in
